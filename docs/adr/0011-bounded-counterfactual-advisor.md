# ADR-0011：受限反事实建议器；只搜索同机型、同台数的 Pareto 切分

- 状态：**Accepted → 当前三个模型页面均已在 `app.html` 实施**（2026-09-15）
- 触发：roofline 能解释当前配置的瓶颈,但用户还需要回答「在这台机器上,下一步可以改什么」
- 影响：**部分取代** [ADR-0005](0005-validator-not-solver-and-instance-list.md) §1 的「不做配置枚举、不做排序推荐」和 [ADR-0010](0010-decode-roofline-lower-bound.md) 的「只对当前配置给数」。不改变成本 / 可得性边界,也不引入全局最优解。

## 问题

只对当前 `(instance, 台数, TP, DP, PP, EP)` 给 roofline 数字,仍然会留下「so what」:

- 换机型反事实沿用原来的并行切分,没有回答新机型上怎样切。
- 手工预设只覆盖少数教学案例,不会随目标、dtype、上下文和 util 自动变化。
- 用户能看见瓶颈,却还要自己逐个枚举合法切分并比较。

但直接做全局求解器同样不可信。价格、可得性、kernel 成熟度、PP 气泡、集合通信延迟与效率系数都不在模型里;「最低延迟」「最高吞吐」「最大容量」也互相冲突。

## 决议

增加一个**受限反事实建议器**,边界如下:

1. 只在当前模型、当前机型、当前实例数内搜索。
2. 固定当前并发、上下文、util、KV dtype、权重格式与 PP。
3. 枚举满足 `TP × DP × PP = world`、`EP | stage`、`EP | nExperts` 的 TP / DP / EP 切分。
4. 不新引入 `TP > NVLink domain` 的组合。当前 roofline 没有集合通信延迟,否则搜索会虚假偏爱跨节点大 TP。
5. 丢弃当前负载装不下的组合。
6. 按用户选定目标计算:
   - 降低延迟：最小化当前负载的 ITL 下界。
   - 提高吞吐：最大化当前负载的吞吐上界。
   - 增加容量：最大化当前口径下的完整请求数。
7. 不把冲突目标压成一个加权总分。只保留目标指标与主要副指标组成的 Pareto frontier,最多展示两个候选。
8. 每个候选必须同时展示代价：容量或 ITL 的变化、EP 是否跨 NVLink 域和通信下界。
9. 文案使用「同机型切分可尝试」「Pareto 改善」,不使用「最优配置」「应该部署」。

建议按钮只修改页面输入,不修改任何部署。

## 明确不做

- 不搜索其他机型或实例数。
- v1 不搜索 PP。PP send/recv、pipeline bubble 与 stage 不均衡尚未进入 roofline,不能把 `KV ÷ PP` 的显存收益当成免费优化。
- 不推荐新引入跨 NVLink 域的 TP。带宽项不足以代表每层两次 all-reduce 的真实延迟。
- 不比较价格、region、Capacity Blocks 或供应情况。
- 不声称 roofline 排名等于实测排名。
- 不隐藏模型缺项:PP 气泡、通信延迟、kernel / 调度固定开销仍需 benchmark。
- 不把不可比较的目标合并成单一推荐分数。

## 后果

- 页面从纯校验器变成「校验器 + 有边界的反事实建议器」。
- ADR-0005 的核心警告仍然成立:工具不能替用户做采购或全局价值判断。
- 切分枚举空间只由当前 `world` 的约数组成。当前 8/16/32 卡配置只有几十个合法组合,可在每次渲染时直接计算,无需缓存或后台任务。
- 已对当前三个模型的 family 约束分别验证:
  - Kimi K3：可降低 TP、提高 DP 来减少 MLA KV 副本；没有改善时不重复动作卡。
  - GLM-5.3-Flash：长上下文下能识别 TP8/DP1 → TP1/DP8 的 KV 复制收益。
  - DeepSeek-V4.1-Flash：p5en 上 TP1/TP2 因 engram 装不下而被过滤,TP4/DP2 可保留；架构固定的 FP4 KV 不生成 dtype 建议。
