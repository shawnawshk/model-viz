# ADR-0015：界面支持简体 / 繁体 / English；只维护简体与英文，繁体由 OpenCC 现转

- 状态：**Accepted → 已在 `i18n.js` + `app.html` + `index.html` + `sidebar.js` + 6 个 data 文件实施**（2026-10-30）
- 触发：用户要求页面支持简 / 繁 / EN 三种语言切换
- 影响：
  - 新增 `i18n.js`（classic script，在两个页面里排在 `data/instances.js` 之前）与 `vendor/opencc-js/`。
  - 页面里每段可见文案改成 `L(简体, 英文)`；静态标记用 `data-en` / `data-en-title` / `data-en-aria-label`。
  - data 契约：每个要显示的字段旁边加英文孪生字段（`blurbEn`、`notesEn`、`labelEn`、`nameEn`、`tpShardedLabelEn` 等）。
  - `verify-app.js` 新增四组检查（见「验证」）。
- 相关：[ADR-0002](0002-page-per-model.md)（零构建、`file://` 可用）、[ADR-0004](0004-provenance-first-class.md)（数字与口径不能脱节）

## 决议

### 1. 只维护两份文案

| 语言 | 来源 |
|---|---|
| 简体（`zh-Hans`） | 原文，写在 `L()` 的第一个参数、数据文件的原字段 |
| English（`en`） | 写在 `L()` 的第二个参数、数据文件的 `xxxEn` 字段 |
| 繁体（`zh-Hant`） | 页面加载时用 OpenCC 从简体现转（`from: "cn", to: "twp"`，台湾用语） |

繁体不单独维护，是因为三份文案同步的成本比两份高一半，而简繁之间可以机器转换，英文不行。用台湾用语，与姊妹项目 `kimi-k3-reference` 的 zh-TW 版一致。

OpenCC 的台湾词表在本工具的语境里有 6 处是错的，`i18n.js` 的 `HANT_TERMS` 在转换前先把这些词保护起来：

| 简体 | OpenCC 给 | 本页用 | 原因 |
|---|---|---|---|
| 显存 | 視訊記憶體 | 顯存 | 姊妹项目的 zh-TW 版用「顯存」 |
| 参数 | 引數 | 參數 | 「引數」是编程里的 argument |
| 实例 | 例項 | 執行個體 | AWS 台湾版文档的用法 |
| 声明 | 宣告 | 聲明 | 「宣告」是编程里的 declaration |
| 复制 | 複制（在「被复制了」里） | 複製 | 分词切错了 |
| 激活 | 啟用 | 激活 | 「激活峰值」说的是 activation，不是 enable |

### 2. 加载与切换

- 判定顺序：`?lang=` > 上次的选择（localStorage `viz-lang`）> 浏览器语言。`zh-TW / zh-HK / zh-MO / zh-Hant` → 繁体，其余 `zh` → 简体，其余 → English。
- 带 `?lang=` 打开也会记住，这样从分享链接进来的人在站内跳转时语言不变。
- 切换语言会带上 `?lang=` 重新载入页面。滑块状态不保留。代价是切一次要重设参数；好处是不用为每个静态元素保存原文再重渲染。
- OpenCC 的词典有 1.1 MB，只在繁体时由 `document.write` 在解析阶段同步插入。简体与英文用户不下载它，`file://` 下照样能用。

### 3. 数据文件里的英文

- 引擎在加载时把要显示的字段一次性换成当前语言（简体下原样不变），之后所有引用 `.label` / `.name` / `MD.notes` 的地方自动跟着变。
- 英文必须保留中文里的每一个数字、每一个 `<code>` 片段、每一个链接。数字的比对认得千分位、「X 亿」= X×100 M、「X 万」= X/100 M。
- 预设名里的「推荐」照原文译成 Recommended（K3 那个预设是历史遗留，改不改中文原名不在本 ADR 范围内）。

## 不做

- `docs/` 下的 ADR、README、glossary 不翻译。它们是给维护者看的。首页「计算说明」的链接在英文页上标了 (Chinese)。
- `throw new Error` 与 `console.warn` 的开发者信息不翻译。
- 数字格式不本地化（一律 `en-US` 的千分位），单位 GiB / B/token 不翻译。

## 验证

`verify-app.js` 新增四组检查，各抓一种错法：

1. **静态标记**：用一个小的 HTML tokenizer 扫两个页面，每段带汉字的文本都要在某个 `data-en` 元素里；每个带汉字的 `title` / `aria-label` 都要有 `data-en-*`；`data-en*` 里不许有汉字。
2. **数据文件**：每个要显示的字段都有 `xxxEn`；中英两版的数字、`<code>` 片段、链接逐个一致；英文里不许有汉字。
3. **渲染**：6 个模型与首页在英文、繁体下各渲染一次。不许有 `undefined` / `NaN`；英文输出里不许剩汉字（全角标点也算）；繁体输出逐字检查，`cn → tw` 字形转换还会改动的字就是漏转的简体字。
4. **语言判定**：10 种「参数 / 上次选择 / 浏览器语言」的组合。

原有 43 条用例固定用 `?lang=zh-Hans` 跑，断言一个字不改。重构前后，简体下 43 个用例 + 首页的每个容器输出**逐字节相同**（快照对比）。四组新检查各故意弄坏一处，都能报出来。

## 维护规则

改任何可见的中文文案，都要同时改英文。漏了 verify 会报：英文页面上剩汉字，或中英数字对不上。
