# ADR-0006：单位口径 —— 内部以字节为真值，UI 一律显示 GiB

- 状态：**Accepted → 已在 `index.html` 实施**（2026-08-31）
- 影响：整个计算模型与全部 UI 数字

## 实施结果（推荐配置 TP8×DP4/EP32、util 0.90、128K）

| 量 | 修正前 | 修正后 |
|---|---|---|
| 每卡物理显存 | 141 × 10⁹ B | **144384 MiB = 141 GiB** |
| util 0.90 预算 | 126.9（十进制 GB） | **127 GiB** |
| 单卡峰值占用 | 121 | **114 GiB** |
| **128K 下最大并发** | **107 路** | **126 路（+18%）** |
| 集群权重总存量 | 2.06 TB | **1.88 TiB** |
| routed expert 总量 | 1446 | **1347 GiB** |

实施中踩到一个自身的坑：`fgb → fgib` 重命名漏了一处裸 `gb()` 调用（权重总存量 tile），导致 `render()` 在 banner 之后静默抛异常、tiles/节点网格/两个表格全空。**教训：这类全局重命名必须跑一次脚本执行验证，不能只看渲染出来的上半部分。** 现已加入验证流程（DOM stub 下 require 整段脚本）。

## 触发原因：一个已发现的真 bug

`index.html` 中 `HW.gpuMem = 141e9`，即把 H200 的「141 GB」当成 141 × 10⁹ 字节。

`describe-instance-types` 返回 H200 为 **144384 MiB = 141 GiB = 151,397,302,272 字节**。

**旧值低估 7.4%**：每卡少算 10.4 × 10⁹ 字节，32 卡少算 333 × 10⁹ 字节。推荐配置（TP8×DP4/EP32、util 0.90、128K）的最大并发由 107 路修正为约 128 路。所有此前给出的容量数字都受影响。

## 为什么必须改口径，而不只是改一个常数

厂商与 AWS spec 页标称的「GB」在不同 GPU 上含义不同，**无统一规律**：

| GPU | API MiB | 标称 | 标称实为 |
|---|---|---|---|
| T4g | 16384 | 16 GB | GiB |
| A10G / L4 | 22888 | 24 GB | **十进制** |
| L40S | 45776 | 48 GB | **十进制** |
| RTX PRO 4500 | 32768 | 32 GB | GiB |
| RTX PRO Server 6000 | 98304 | 96 GB | GiB |
| A100 / H100 | 40960 / 81920 | 40 / 80 GB | GiB |
| H200 | 144384 | 141 GB | GiB |
| B200 | 183359 | 180 GB | ≈GiB（含 ECC 保留） |
| B300 | 275040 | 288 GB（NVIDIA） | **十进制** |

数据中心卡按 GiB 标，Ada 衍生卡按十进制标，B300 又回十进制。只要工具接受多个 instance，「拿标称数字当某一种单位」必然出错。

## 决议

1. **唯一真值是 `describe-instance-types` 的 `MemoryInfo.SizeInMiB`。** instance json 存 MiB，不存任何「GB」。
2. **内部计算全部用字节。** `bytes = MiB × 1048576`。
3. **UI 一律显示 GiB**（`bytes / 2^30`）。选 GiB 而非十进制 GB，是为了与 AWS/NVIDIA 对数据中心卡的标称对得上（141 GiB、1128 GiB），使用者能把界面数字与 spec 页直接比对。
4. **不混用。** 不出现「GB」字样；不在同一界面同时给两种单位。
5. KV cache、权重、overhead 等派生量同样以字节计算、以 GiB 显示。

## 后果

- `index.html` 现有全部显示数字会变大约 7.4%（容量侧），需重新截图核对。
- `fgb()` 更名为 `fgib()`，除数由 `1e9` 改为 `2**30`。
- 假设区需新增单位说明，并保留本 bug 的记录，避免将来有人「修回」十进制。
- `docs/instance-specs.md` 已同时列出 MiB / GiB / 十进制 GB 三列，作为核对依据；该表是本 ADR 的证据。

## 一个未消除的残余不确定

`SizeInMiB` 是**标称**容量。实际 `nvidia-smi` 报告的可用显存通常略低（ECC 与固件保留），例如 H100 标称 81920 MiB、实报约 81559 MiB。差值在千分之几量级，被 `gpu_memory_utilization` 吸收，因此不单独建模；但 `measured` 级别的 overhead 实测（见 ADR-0004）会自动把这部分包含进去。
