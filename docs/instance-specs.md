# AWS GPU 实例规格清单（G5–G7 / P4d–P6）

## 这份文件的用途

**这是规格总目录，供查阅与去重——任何 instance 的规格都从这里取，不要每次去拉 API。**

它**不**决定工具支持哪些 instance。每个模型的候选 instance 列表写在该模型自己的 json（`candidateInstances`）里，建那个模型页面时单独与用户确认。「哪些机型值得为某个模型考虑」是业务判断，不从本目录自动推导。见 ADR-0005 §2。

**口径：以 `describe-instance-types` 返回的 `MiB` 为唯一真值。** 其余单位全部由它派生。UI 显示统一用 GiB（ADR-0006）。

抓取时间 2026-08-31，region `us-west-2`。复现命令：

```bash
aws ec2 describe-instance-types --region us-west-2 \
  --filters Name=instance-type,Values='g5.*,g5g.*,g6.*,g6e.*,g6f.*,gr6.*,gr6f.*,g7.*,g7e.*,p4d.*,p4de.*,p5.*,p5e.*,p5en.*,p6*' \
  --query 'InstanceTypes[].[InstanceType,GpuInfo.Gpus[0].Name,GpuInfo.Gpus[0].Count,GpuInfo.Gpus[0].MemoryInfo.SizeInMiB,NetworkInfo.EfaSupported,NetworkInfo.EfaInfo.MaximumEfaInterfaces,NetworkInfo.NetworkPerformance]' \
  --output text | sort
```

## ⚠️ 单位陷阱（必读）

厂商与 AWS spec 页标称的「GB」**在不同 GPU 上含义不同**，没有统一规律：

| GPU | API MiB/卡 | = GiB | = 十进制 GB | 标称 | 标称实为 |
|---|---|---|---|---|---|
| T4g | 16384 | **16.0** | 17.2 | 16 GB | GiB |
| A10G / L4 | 22888 | 22.4 | **24.0** | 24 GB | 十进制 |
| L40S | 45776 | 44.7 | **48.0** | 48 GB | 十进制 |
| RTX PRO 4500 | 32768 | **32.0** | 34.4 | 32 GB | GiB |
| RTX PRO Server 6000 | 98304 | **96.0** | 103.1 | 96 GB | GiB |
| A100 40 / H100 | 40960 / 81920 | **40 / 80** | 42.9 / 85.9 | 40 / 80 GB | GiB |
| A100 80 | 81920 | **80.0** | 85.9 | 80 GB | GiB |
| H200 | 144384 | **141.0** | 151.4 | 141 GB | GiB |
| B200 | 183359 | 179.1 | 192.3 | 180 GB | ≈GiB（含 ECC 保留） |
| B300 | 275040 | 268.6 | **288.4** | 288 GB（NVIDIA） | 十进制 |

数据中心卡（A100/H100/H200）按 GiB 标；Ada 衍生卡（A10G/L4/L40S）按十进制标；B300 又回到十进制。**因此任何计算都必须从 MiB 出发，不能拿标称数字直接当十进制 GB 用。**

> **已知影响**：`index.html` 现用 `gpuMem: 141e9`，即把 H200 的 141 当十进制 GB。真值为 `144384 MiB = 151.4e9 字节`，**低估 7.4%**（每卡 10.4 GB，32 卡 333 GB）。修正后推荐配置的最大并发从 107 路升至约 128 路。待修。

## NVLink / NVSwitch

**NVLink 是 P 系列独占，G 系列一张都没有。** G7/G7e 多卡型号 spec 表写的是「Yes via PCIe」——那是 PCIe P2P，不是 NVLink。

| 实例族 | NVSwitch P2P | 来源 |
|---|---|---|
| p4d / p4de | 600 GB/s | spec 页 |
| p5 / p5e / p5en（48xlarge） | 900 GB/s | spec 页 |
| p6-b200 / p6-b300 | 1800 GB/s | spec 页 |
| p5.4xlarge（单卡） | N/A | spec 页 |
| G5 / G5g / G6 / G6e / Gr6 | 无 | spec 表无 P2P 列 |
| G7 / G7e 多卡（12xl+） | 无 NVLink，PCIe P2P | spec 页「Yes via PCIe」 |

API 不返回 NVLink 信息，本表 NVLink 列全部来自 spec 页，级别 `spec`。

## EFA

**EFA 支持是按 size 而非按 family 的。** 所有 G 系列族都遵循同一模式：小 size 不支持，`8xlarge` 及以上才支持。

EFA 代际（来自 spec 页 / 发布公告，API 不返回代际）：

| 实例族 | EFA 代际 | 总带宽 |
|---|---|---|
| p4d / p4de | EFA(v1) | 400 Gbps（4×100） |
| p5 / p5e | EFAv2 | 3200 Gbps |
| p5en | EFAv3 | 3200 Gbps |
| p6-b200 | EFAv4 | 3200 Gbps |
| p6-b300 | EFAv4 | 6400 Gbps |
| g7e | EFAv4 | 1600 Gbps |
| g7 | EFA（代际未公开声明） | 700 Gbps |
| g6 / g6e | EFA（代际未公开声明） | 100 / 400 Gbps |
| g5 | EFA（代际未公开声明） | 100 Gbps |
| g5g | 不支持 | — |

## 派生结论

### 能承载大模型的候选（≥8 卡且有 NVLink）

只有 5 个：`p4d.24xlarge`(320 GiB) / `p4de.24xlarge`(640 GiB) / `p5.48xlarge`(640 GiB) / `p5e`·`p5en.48xlarge`(1128 GiB) / `p6-b200`(1433 GiB) / `p6-b300`(2149 GiB)。

G 系列即便 8 卡（`g6e.48xlarge` 358 GiB、`g7e.48xlarge` 768 GiB）**也没有 NVLink**，卡间只能走 PCIe，因此不适合需要高 TP 的模型；它们的定位是单卡/少卡推理。

### 对 Kimi K3（权重约 1.6 TB）的直接影响

| 实例 | 每实例 GiB | 装下 1.6 TB 权重最少台数 |
|---|---|---|
| p5en.48xlarge | 1128 | 2（但 KV 余量极少，实用 4） |
| p6-b200.48xlarge | 1433 | 2 |
| p6-b300.48xlarge | 2149 | **1（权重）/ 2（含 KV）** |
| g7e.48xlarge | 768 | 3，但无 NVLink → 不可用 |

### 数据质量

| 字段 | 来源 | 级别 |
|---|---|---|
| GPU 型号 / 数量 / MiB | `describe-instance-types` API | `spec`（权威） |
| EFA 支持 / 接口数 | 同上 | `spec`（权威） |
| 网络带宽 | 同上（字符串，需解析） | `spec` |
| NVSwitch GB/s | AWS spec 页 | `spec` |
| EFA 代际（v1–v4） | spec 页 / 发布公告；**G 系列未公开声明** | `spec` / 部分缺失 |

### 未收录

- `p6e-gb200.36xlarge` 及 `u-p6e-gb200x{36,72}` UltraServer：按 ADR-0005 已排除出范围；且 `us-west-2` 的 `describe-instance-types` 不返回该类型。
- `g4dn` / `g4ad`：早于 G5，超出本清单范围。
- `trn*` / `inf*`：非 GPU。
